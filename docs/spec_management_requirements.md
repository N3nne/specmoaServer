# 스펙 관리 분류 및 데이터 명세

작성일: 2026-10-12  
대상: 스펙모아.zip / Stitch `specmoa.zip_ui_2`  
단계: 권장 진행 순서 1단계 - 스펙 분류와 저장 항목 확정  
상태: 1단계 확정 - 테스트 버전의 모든 사용자 입력 항목은 선택

## 1. 범위와 근거

이 문서는 분류, 입력 항목, 상태, 검증 규칙, 원본 화면과의 차이를 정리한 요구사항 명세다. 후속 구현은 이 명세를 기준으로 진행하며, 코드 작업 및 DB 적용 상태는 구현 안내 문서에서 별도로 기록한다.

- Stitch MCP에서 대분류 선택, 세부유형 선택, 8종 입력 화면을 확인했다.
- 입력 화면 8종의 HTML과 원본 스크린샷을 대조했다.
- 기존 Flutter 자격증 등록 화면, 등록 DTO, 사용자 자격증 엔티티 및 저장 서비스와 비교했다.
- 원본 화면에 명시되지 않은 입력칸이나 새로운 UI는 생성하지 않는다.
- 화면에 있는 예시 이름, 날짜, 점수, 기술 태그, 파일명은 실제 데이터나 초기 저장값이 아니다.
- 원본의 별표와 `필수` 문구는 원본 분석 자료로만 보관한다. 최신 사용자 승인에 따라 테스트 버전에서는 모든 사용자 입력 항목을 선택으로 처리하며, 원본의 필수 표시보다 이 정책을 우선한다.
- 기술적인 저장 키는 설계용 표기이며 아직 생성된 DB 컬럼이나 API가 아니다.

## 2. 사용자 승인 사항

| 항목 | 확정된 방향 | 적용 범위 |
| --- | --- | --- |
| 자격증 입력 | 기존 앱 대신 새 Stitch 원본의 입력 항목 사용 | 자격증 번호는 선택, 점수·등급·만료일·키워드 포함, 별도 메모칸 없음 |
| 공식 목록 밖 자격증 | 직접 입력 등록 허용 | 사용자 개인 스펙으로 보관, 공식 종목 목록이나 공식 인증 내역에 자동 추가하지 않음 |
| 테스트 버전 입력 | 8종 등록 화면의 모든 사용자 입력 항목은 선택 | GPA뿐 아니라 이름·기관·날짜·점수·선택 컨트롤·조건부 영역까지 포함, 일부 또는 전체 미입력도 등록 가능 |
| 추후 필수 항목 선정 | 유형별 필수 정책을 분리해 변경 가능하게 설계 | 입력 항목 자체와 형식 검증은 유지하고, 필수 여부는 이후 별도 선정 |
| 준비 중 스펙 | 첫 버전 앱에서 제외 | 미취득 자격증·시험 준비 상태를 새로 등록하지 않음 |
| 진행 중 경험 | 유지 | 원본의 프로젝트 진행 중, 현재 재직 중, 현재 활동 중 및 학적 상태 유지 |
| 증빙파일 | 후순위 | 첫 버전은 텍스트·성적 저장, 파일 업로드·보관·첨부 기능 미포함 |
| 타이머 | 자유 학습 + 선택 연결 | 스펙이 없어도 사용 가능, 등록한 스펙과 선택적으로 연결 |
| 스펙 삭제와 학습 기록 | 연결된 학습 기록도 삭제 | 삭제한 스펙에 연결된 기록만 삭제, 자유 학습 및 다른 스펙 기록 유지 |
| 등록·타이머 UI 적용 | 기존 원본 및 컴포넌트 재사용 승인 | 등록 원본의 필수 표시·준비 중 선택·첨부/OCR·가짜 AI 점수 제거, 타이머 선택 칩은 자유 학습 + 등록 스펙으로 변경 |
| OCR·기관 검증·AI | 후순위 | 원본의 데모 문구를 실제 분석·인증 결과로 저장하거나 표시하지 않음 |

준비 중 등록 제외와 실제 진행 중 활동은 서로 다른 규칙이다. 프로젝트를 현재 수행하는 것, 현재 재직하는 것, 재학 중인 것은 미래 시험을 준비하는 상태와 구분한다.

기존 DB에 남아 있는 준비 자격증은 이 단계에서 삭제하거나 취득 완료로 변환하지 않는다. 이후 마이그레이션에서 보존하고 새로운 앱의 노출 규칙을 적용한다.

## 3. 분류 체계

| 대분류 | 세부유형 | 설계용 식별자 | 등록 대상 |
| --- | --- | --- | --- |
| 시험·성적 스펙 | 자격증 | `certification` | 실제 취득한 자격증 |
| 시험·성적 스펙 | 어학 성적 | `language_score` | 실제 응시 후 얻은 점수·등급 |
| 시험·성적 스펙 | 학점·학력 | `education_record` | 재학·휴학·졸업예정·졸업 등 실제 학적과 성적 |
| 시험·성적 스펙 | 수상·공모전 | `award` | 실제 수상 내역 |
| 활동·경험 스토리 | 프로젝트 | `project` | 진행 중이거나 종료된 프로젝트 |
| 활동·경험 스토리 | 인턴십·실무 | `work_experience` | 현재 재직 또는 종료된 인턴·정규직·계약직 경험 |
| 활동·경험 스토리 | 대외활동·서포터즈 | `external_activity` | 현재 활동 또는 종료된 활동 |
| 활동·경험 스토리 | 교육·부트캠프 | `training` | 원본에 있는 교육 이수·수료 내역 |

교육 원본에는 `현재 수강 중` 스위치가 없고 시작일·수료일 입력칸만 있다. 현재 수강 중 교육도 등록해야 한다면 해당 상태의 원본 UI를 확인해야 하며, 임의로 스위치를 추가하지 않는다.

### 3.1 등록 흐름

1. 대분류를 선택한다. 이 시점에는 DB 내역을 생성하지 않는다.
2. 해당 대분류의 세부유형을 선택한다. 이 시점에도 DB 내역을 생성하지 않는다.
3. 승인된 세부유형의 원본 입력 화면에서 원하는 항목을 입력한다. 테스트 버전에서는 입력하지 않은 항목이 있어도 등록할 수 있다.
4. 최종 등록 시에만 로그인·소유권·선택 유형과 입력한 값의 형식을 검증하고 저장한다. 모든 사용자 입력칸이 비어 있어도 서버가 소유자·유형·고유 ID를 가진 내역을 생성할 수 있어야 한다.
5. 저장 성공 후 내 스펙 목록과 실제 등록 개수를 갱신한다.

원본의 `STEP 1 OF 2`, `STEP 2 OF 2`는 유형 선택 화면에 있는 표현이다. 이를 근거로 임의의 새로운 3단계 UI나 화면을 생성하지 않는다. 1단계 원본의 하단 `등록하기` 버튼은 실제 DB 저장이 아닌 다음 선택 화면 이동과 의미가 다르므로, UI 구현 전에 버튼 문구·이동 범위를 확인한다.

## 4. 공통 저장 규칙

| 정보 | 입력/생성 방식 | 규칙 |
| --- | --- | --- |
| 스펙 ID | 서버 생성 | 등록 후 상세·수정·삭제와 타이머 연결의 기준 |
| 소유 사용자 | 서버의 검증된 로그인 정보 | 사용자가 입력한 사용자 ID를 소유권의 근거로 사용하지 않음 |
| 대분류·세부유형 | 선택 흐름 | 세부유형에서 대분류를 결정, 별도 중복 입력칸을 만들지 않음 |
| 표시 제목 | 입력된 유형별 이름에서 생성 | 이름 미입력을 허용, 실제 이름을 임의로 생성하거나 빈 제목 내역들을 같은 스펙으로 취급하지 않음 |
| 등록·수정 시각 | 서버 생성 | 정확한 시각 저장, 표시할 때 지역 시간대로 변환 |
| 취득·시험·수상일 | 사용자 입력 | 날짜만 저장, 시각 변환 때문에 하루가 바뀌지 않도록 함 |
| 프로젝트·근무·활동 기간 | 사용자 입력 | 원본의 월 단위 정확도 유지: `YYYY-MM` |
| 교육 기간 | 사용자 입력 | 원본의 일 단위 정확도 유지: `YYYY-MM-DD` |
| 실제 진행 상태 | 유형별 규칙 | 취득·수상, 학적, 진행·재직 상태를 하나의 공통 준비 상태로 섞지 않음. 사용자 상태 선택의 미입력과 명시적인 선택을 구분 |
| 인증 여부 | 첫 버전 미검증 | 직접 입력·등록만으로 공식 인증 완료 처리하지 않음 |
| 파일 정보 | 첫 버전 없음 | 파일명·첨부 완료·인증 완료 예시를 저장하지 않음 |
| 태그 | 원본 입력 기능이 있는 유형만 | 기술 스택·역량 키워드와 기존 자격증 분야 태그를 구분 |

### 4.1 공통 검증

- 테스트 버전의 모든 사용자 입력 항목은 선택이다. 문자열의 앞뒤 공백 제거 후 빈 값도 미입력으로 취급하고 등록을 거부하지 않는다.
- 미입력은 누락 또는 `null`로 보관한다. `0`, `-`, `없음`, 예시 데이터나 선택 컨트롤의 데모 기본값으로 채우지 않는다. 숫자 0이나 불리언 `false`를 실제 입력한 경우에는 미입력과 구분한다.
- 점수와 만점, 평점과 평점 기준, 등급과 시험 종류는 각각 선택 항목이다. 한쪽만 입력해도 저장할 수 있으며, 짝이 되는 정보를 추정해 채우지 않는다.
- 입력한 날짜만 실제 달력에 존재하는 날짜로 검증한다.
- 월 단위 정보에 임의의 1일을 붙여 정확한 날짜인 것처럼 표시하지 않는다.
- 시작·종료 시점을 모두 입력한 경우에만 순서를 검증한다. 시작이나 종료 중 한쪽만 입력해도 저장할 수 있다.
- 현재 진행·재직·활동 중을 명시적으로 선택하면 종료월은 비워둔다. 상태 미선택을 진행 중 또는 종료로 임의 판정하지 않으며, 예시 종료월을 그대로 저장하지 않는다.
- 실제 취득·성적·수상·수료 기록은 미래 날짜를 완료 내역으로 저장하지 않는다. 실제 진행 중 경험은 종료 시점이 없는 상태로 구분한다.
- 과거에 만료된 성적·자격증도 보관할 수 있다. 만료는 삭제와 구분한다.
- URL을 입력한 경우에만 올바른 HTTP(S) 주소인지 검증하며 첫 버전에서 자동 크롤링하지 않는다.
- 태그는 공백과 앞의 `#`를 정리하고 중복을 제거한다. 원본에서 확인한 개수 제한만 적용한다.
- 입력 수정 시 선택 항목을 비우면 기존 값을 실제로 지울 수 있어야 한다. 누락과 명시적인 삭제를 구분한다.
- 동일 항목을 다시 등록했다고 기존 기록을 조용히 덮어쓰지 않는다. 유형별 중복 정책은 아래 규칙으로 구분한다.
- 만료일·환산 점수·기간·진행률 등 파생값은 필요한 입력과 검증된 계산 규칙이 있을 때만 생성한다. 미입력을 계산 완료·만료 없음·0점·100%로 표시하지 않는다.

문자열 최대 길이처럼 원본에 없는 제한은 임의로 확정하지 않는다. API 설계 단계에서 저장 용량·접근성·입력 UX를 검토해 별도 명세한다.

### 4.2 필수 정책의 변경 가능성

- 필수 여부는 유형별 필드 정책으로 분리한다. 테스트 버전의 8개 유형 모두 사용자 입력의 필수 필드 목록은 비어 있다.
- 필수 여부와 입력값의 형식·범위·길이 검증은 별개의 규칙이다. 선택 항목이라도 값을 입력하면 해당 형식 검증을 적용한다.
- UI의 필수 표시·등록 버튼 활성 조건과 API 검증은 같은 정책을 따라야 한다. UI만 선택으로 바꾸고 서버에서 미입력을 거부하는 상태를 만들지 않는다.
- 소유 사용자·고유 ID·세부유형은 정상 저장에 필요한 시스템 정보다. 사용자 입력칸의 필수 여부와 구분하며, 클라이언트가 전달한 소유자 ID를 그대로 신뢰하지 않는다.
- 이후 필수 항목을 선정하더라도 기존의 미입력 내역을 삭제하거나 예시 값으로 채우지 않는다. 신규 등록·수정에 적용할 시점과 기존 내역의 보완 정책을 별도로 정한다.
- 이 정책을 위해 새로운 설정 화면이나 관리자 UI를 임의로 추가하지 않는다. 실제 정책 파일·DTO·DB 변경은 후속 구현 단계에서 진행한다.

## 5. 유형별 입력 명세

모든 표는 승인된 테스트 버전 입력 정책을 나타낸다. `선택`은 조건부 영역의 입력칸에도 적용한다. `시스템`은 사용자 입력이 아닌 생성·계산 규칙이며, `입력칸 없음`과 `첫 버전 제외`는 새 입력 기능을 추가한다는 뜻이 아니다.

## 6. 수정·중복·삭제 규칙

### 6.1 수정

- 입력 정보를 수정하더라도 기존 스펙 ID와 학습 기록의 연결은 유지한다.
- 같은 학교의 학점 갱신, 진행 중 경험의 종료 처리 등은 기존 내역 수정으로 처리할 수 있어야 한다.
- 세부유형 변경은 일반 수정으로 처리하지 않는다. 다른 유형의 저장 항목 손실을 막기 위해 별도 승인·전환 정책이 필요하다.
- 이미 등록된 스펙의 빈 선택 항목을 수정 요청에서 명시적으로 지울 수 있어야 한다.
- 취득 상태와 공식 인증 상태를 혼동하지 않는다. 첫 버전 등록은 사용자 신고 내역이다.

### 6.2 중복

| 유형 | 중복을 구분할 기준 | 처리 원칙 |
| --- | --- | --- |
| 자격증 | 사용자 + 공식 종목 또는 직접 입력 종목 | 기존 같은 종목을 조용히 덮어쓰지 않음, 갱신 이력 정책은 API 설계 전 결정 |
| 어학 | 사용자 + 시험 종류 + 응시일 | 재응시 성적 여러 건 보관 가능, 최신 성적으로 이전 기록을 자동 삭제하지 않음 |
| 학력 | 학교 + 학위 + 전공 | 여러 학력 보관 가능, 같은 학력의 GPA 갱신은 수정 |
| 수상 | 대회명 + 수상일 + 훈격 | 서로 다른 연도·훈격의 수상 내역 보관 가능 |
| 프로젝트·근무·활동·교육 | 유형 + 이름/기관 + 기간 | 이름이 같아도 기간이 다르면 별도 경험, 자동 덮어쓰기 금지 |

비교에 필요한 항목이 빠져 있으면 위 기준으로 중복을 확정하지 않는다. 빈 이름·`null` 종목 ID·누락 날짜가 같다는 이유로 여러 내역을 한 건으로 합치지 않는다. 식별 정보가 없는 등록도 각각 새 고유 ID를 가지며, 기존 내역 수정은 스펙 ID로 명시한다.

### 6.3 삭제

- 사용자가 삭제를 요청한 스펙만 대상으로 하며 기존 준비 자격증을 일괄 삭제하지 않는다.
- 사용자 추가 승인에 따라 스펙 삭제 시 해당 스펙에 연결된 학습 기록도 삭제한다. 자유 학습 및 다른 스펙 기록은 유지한다.
- 학습 시간 집계에는 실제 남은 기록을 반영하며, 연결되지 않은 기록이나 사용자의 모든 기록을 일괄 삭제하지 않는다.

## 7. 자유 학습 타이머 연결

승인된 방향은 자유 학습을 기본으로 하고 등록된 스펙에 선택적으로 연결하는 것이다.

- 스펙이 0개여도 시작·정지·학습 기록 저장이 가능해야 한다.
- 학습 기록은 특정 자격증 종목이 아니라 선택한 사용자 스펙 ID에 연결할 수 있어야 한다.
- 연결하지 않은 기록은 자유 학습 기록으로 보관한다.
- 타인의 스펙에 학습 기록을 연결할 수 없어야 한다.
- 기존 학습 기록의 자격증 연결과 누적 시간은 마이그레이션에서 보존한다.
- 자유 학습 선택, 미연결 상태, 연결된 스펙 표시의 UI 원본은 별도 확인 후 구현한다.

후속 코드 작업에서는 기존 타이머 화면과 선택 칩을 재사용해 자유 학습 및 선택 스펙 연결을 구현한다.
